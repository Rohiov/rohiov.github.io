🎯 PROMPT MAESTRO - PROYECTO CORA
Sistema Modular de Control de Recursos - ASP.NET Core MVC
📋 CONTEXTO GENERAL DEL PROYECTO
Estoy desarrollando CORA (Sistema Modular de Control de Recursos), una aplicación web empresarial basada en ASP.NET Core MVC con .NET 10.0.11, diseñada para ser altamente modular mediante un sistema de plugins que permite agregar nuevos módulos sin recompilar el núcleo del sistema.

Filosofía del Proyecto
Modularidad extrema: Cada módulo es autocontenido (tablas propias, controladores, vistas, servicios)

Sin recompilación del núcleo: Agregar un módulo = copiar carpeta + Module.json + recargar

Roles granulares: Roles globales (Superusuario, Administrador) + roles por módulo (Usuario Estándar, Aprobador)

Autenticación híbrida: Windows (Negotiate/Kerberos) para usuarios de dominio + login especial para Superusuario

Auditoría completa: Todos los cambios quedan registrados

🧩 MÓDULO: SISTEMA DE PLUGINS
Cómo Agregar un Nuevo Módulo
text
PASO 1: Crear carpeta en wwwroot/modules/MiNuevoModulo/
PASO 2: Agregar Module.json con configuración y roles
PASO 3: Copiar MiNuevoModulo.dll
PASO 4: Admin → Módulos → [🔄 Recargar Módulos]
PASO 5: El sistema:
        • Detecta el módulo
        • Registra en tabla Modulos
        • Crea roles en tabla Roles (Tipo='Local')
        • Registra menús en ModulosAdminMenu (Tipo='Catalogo')
        • Ejecuta scripts SQL para crear tablas del módulo
PASO 6: Administrador ve los nuevos menús en "Catálogos"

5. REGLAS DE NEGOCIO CONSOLIDADAS
5.1 Acceso y roles
Superusuario: acceso TOTAL. Solo asignable al Superadmin (Id=2).

Administrador: acceso total al panel Admin. Asignable por Superadmin.

Generador: rol local. Crea salidas.

Aprobador: rol local. Solo aprueba/rechaza (NO crea).

Solicitables: solo Generador (por RolesSolicitables.Codigos).

Usuarios se crean automáticamente al primer login Windows (CreadoPor=1).

5.2 Estados de Salida
text
Borrador → PendienteAprobacion → Aprobada (inmutable)
                               → Rechazada (inmutable)
                               → Cancelada (editable 1 día)
Clonable desde: Aprobada, Rechazada, Cancelada
Borrador: folio NULL, editable, eliminable.

PendienteAprobacion: folio 8 dígitos, cancelable solo 1 día por dueño.

Aprobada/Rechazada: inmutables.

Cancelada: editable 1 día.

5.3 Salidas
Mín 1 material, máx 50.

Cantidad > 0.

Sin descripciones duplicadas (comparar por Descripción).

Folio secuencial de 8 dígitos, GenerarFolioSecuencialAsync con transacción Serializable.

Aprobador ≠ creador.

Al aprobar no requiere comentario (campo eliminado).

PDF solo para salidas aprobadas.

5.4 Empresas, Unidades, Tipos de Empresa
Nada se elimina — solo se desactiva (EsActivo).

Empresa cambia de tipo cambiando IdTipoEmpresa.

Tipos y Unidades se crean desde el panel Admin.

En el modal de Empresa hay un botón "Ver todos" que abre modal anidado de Tipos con opción "Agregar Nuevo Tipo".

5.5 Módulos
Los módulos NO se eliminan, solo se deshabilitan.

Se descubren al escanear wwwroot/modules/ con su Module.json.

Los roles locales se registran automáticamente al cargar.

5.6 Solicitudes de acceso
Usuario sin roles → /SolicitarAcceso.

Solicita un módulo y un rol (solo los de RolesSolicitables).

Debe elegir un aprobador (usuario con PuedeAprobar=true).

Al aprobar, se crea UsuarioRol automáticamente.

11. GLOSARIO DE TÉRMINOS
Término	Significado
Módulo	Plugin MEF cargado dinámicamente (ej: SalidasMaterial)
Área	Concepto MVC de ASP.NET Core para agrupar controladores/vistas
Árbol de permisos	Jerarquía de Permisos con IdPadre auto-referencial
RolesPermisos	Relación N:M que asigna nodos hoja a roles
Folio	Identificador único de 8 dígitos generado al enviar a aprobación
Aprobador cruzado	Aprobador distinto del asignado que aprueba por tener el rol
Clonación	Crear nueva salida en Borrador a partir de una Aprobada/Rechazada/Cancelada
Solicitable	Rol que un usuario estándar puede pedir desde /SolicitarAcceso
Delegación	Método de gestión desde el agregado raíz (Salida gestiona SalidaDetalle)
Composición	Relación todo-parte fuerte (parte NO existe sin el todo)
Agregación	Relación todo-parte débil (parte existe sin el todo)
